## 1. Hugging Face Spaces: what is actually true

Researched against Hugging Face's own documentation. Two findings matter more than the rest.

| | Free CPU Basic |
|---|---|
| Compute | 2 vCPU |
| RAM | **16 GB** (you said 12 — the real figure is 16, but budget to ~9) |
| Disk | 50 GB, **ephemeral — wiped on every rebuild** |
| Sleep | after ~48 hours idle; cold start roughly 30–90 s |
| Sleep timer | **not configurable** on cpu-basic |
| Visibility | public by default; private Spaces are a paid feature |
| ZeroGPU | quota-based H200/A100 access, on the order of minutes per day, Gradio/Docker only |
| Upgrade | CPU Upgrade is 8 vCPU / 32 GB at $0.03/hr |

### Finding 1 — Static Spaces are free for everyone; compute Spaces are not

Hugging Face's docs state that CPU Basic has no hourly cost, **but that creating a Space which runs on compute (Gradio or Docker) requires a paid plan, while Static Spaces are free for everyone.** This appears on both the Spaces overview and the GPU-hardware pages.

This is close to the best possible news, because **Overtone is a static app.** Parts I–III put the whole engine in WASM specifically so the demo needs no backend. A Static Space serves HTML, JS and WASM — exactly what we produce.

**So: ship the demo as a Static Space.** Free for everyone, no plan required, no sleep problem for static assets, and a `*.hf.space` URL that lends the project the Hugging Face audience for nothing. Mirror it on GitHub Pages so neither host is a single point of failure.

*(Hugging Face changes pricing. Re-check both doc pages at build time and put the check in the release checklist rather than trusting this table.)*

### Finding 2 — the nightly compute should be GitHub Actions, not a Space

Part III's Atlas needs a machine that runs sweeps on a schedule. A free Space is the wrong tool: it sleeps at 48 hours, its disk is wiped on rebuild, and it now needs a paid plan anyway.

GitHub Actions on a public repository is the right tool. Free runners, roughly 4 vCPU and 16 GB, multi-hour job limits, cron scheduling, and no sleep semantics at all. The nightly job runs the sweep and pushes results to a **Hugging Face Dataset**, which is free, versioned, and — unlike a Space — designed to be a durable artifact.

*(Runner specs for public repos have changed more than once; verify current limits before relying on the numbers.)*

### The resulting three-tier architecture

```
Tier 0  Static Space + GitHub Pages     WASM demo. No backend. Always works.
Tier 1  GitHub Actions (nightly cron)   Sweeps → HF Dataset (the Atlas).
Tier 2  Compute Space (optional, Pro)   Live /predict and /dequantize endpoints.
```

Tier 2 is a nice-to-have and must never be a dependency. If it is asleep or absent, the UI shows the cached Atlas answer, labels it as cached, and carries on. **A demo that breaks when a free Space sleeps is a demo that is broken half the time.**

Memory ceiling stands: `16 · 2ⁿ` bytes per `complex128` state vector, two live for adjoint gradients, budgeted to 9 GB, gives **28 qubits with gradients**. Beyond that, `g-sim` and MPS from Part III.

## 2. On characters — I pushed back before, and here is what changed

Part II said no sprites. That still holds: a cartoon in a corridor would make this look like a school project and lose the audience it is built for.

But you are right that the project needs characters, and I was solving the wrong problem. What makes a character is not a body. It is **a distinct identity, a legible personality, and stakes.** All three are available here without drawing a single face — and the version you get from the mathematics is stranger and better than a sprite.

### 2.1 Identity: every agent wears its own algebra

Each agent's visual mark is **computed deterministically from its dynamical Lie algebra**. Take the DLA basis — a set of Pauli strings, each a pair of bitsets from Part III §3 — and render it: strings as radial spokes, `X/Y/Z` support as arc segments, `dim(g)` setting the ring count, the commutator graph's structure setting the symmetry.

This is not an identicon. It is a picture *of the actual mathematical object*, so two agents with the same algebra look identical **because they are the same agent**, and an agent whose algebra explodes toward `4ⁿ` looks visibly denser and more chaotic than one constrained by symmetry. The sigil is a readout, not a decoration.

Design it carefully — this mark ends up on the README, on social cards, and on every agent card in the UI. It is the project's face, and it is generated by the project's own physics.

### 2.2 Personality: a stat block of real observables

Every agent carries a card:

```
  ⟨sigil⟩   ARBITER-7
            coin           learned (SOFTMAX-PQC, L=4)
            dim(g)         84
            reach          |ω| ≤ 4·λ,  λ = 2.91
            transport β    0.94   (near-ballistic)
            effective χ    12     (not classically trivial)
            entropy        0.71
```

Every line is measured, not authored. `β` is the transport exponent from §3. `effective χ` is Part III's dequantization verdict. An agent with `χ = 3` is, in a real sense, a *weak* character — and the interface should let you feel that.

**This is the key move.** Fictional stat blocks are slop. A stat block whose every entry is a physical observable is a *specification sheet*, and specification sheets are how engineers relate to machines they care about. Name the agents; the names are labels on measurements.

### 2.3 Stakes: the race

Four agents, one endless maze, simultaneously: Hadamard coin, Grover coin, learned coin, classical random walk. Four distinguishable amplitude fields spreading through the same corridors, with a live leaderboard of distance-from-origin and arrival probability.

No sprite, and yet you will find yourself wanting the learned one to win. That is what a character is.

## 3. Endless worlds: the maze as a transport dial

"Endless" should not mean "the same maze, scrolling." It should mean **a family of worlds, each with different physics**, generated from one-line rules.

Quantum transport on a lattice obeys `σ(t) ∝ t^β`. Change the substrate and `β` moves continuously across its whole range — and `β` is *measurable live*, which turns world-selection into an experiment rather than a skin.

| World | Rule | Transport exponent `β` |
|---|---|---|
| Periodic lattice | trivial | `1` — ballistic |
| Thue–Morse | substitution `0→01, 1→10` | superdiffusive, `0.5 < β < 1` |
| Fibonacci | substitution `A→AB, B→A` | sub-ballistic; singular-continuous spectrum |
| Rudin–Shapiro | 4-letter substitution | **strongly subdiffusive** — discrete spectrum |
| Random static disorder | per-cell random phase | `β → 0` — Anderson localization |
| Aperiodic monotile ("the Hat") | matching rules | critical states, anomalous transport |
| Hyperbolic `{7,3}` | Poincaré-disc tiling | exponentially growing space |

Every one of these is a few lines of generator code and produces a genuinely different world. Show the measured `β` on screen at all times, with the theoretical regime named beneath it. **The dial is real; the worlds are endless; the readout is a number from a physics paper.**

The Fibonacci and Rudin–Shapiro contrast is worth a panel on its own: two aperiodic sequences, both perfectly ordered, both non-repeating, and one is superdiffusive while the other is strongly subdiffusive. The difference is the nature of the spectrum. That is a genuinely surprising fact and it renders as two side-by-side wavefronts moving at visibly different rates.

The Poincaré-disc rendering of the hyperbolic world is, separately, one of the most beautiful things in mathematics and will earn its own screenshots.

### 3.1 Wave Function Collapse, and the joke that is also a lesson

Generate the maze with **Wave Function Collapse** (Gumin's constraint-propagation algorithm). WFC is beloved in generative art and gamedev and brings an entirely different audience to a quantum RL repository — a real strategic asset.

It also sets up the best piece of exposition available to this project. WFC borrows quantum vocabulary as *metaphor*: tiles in "superposition," an "observation" that "collapses" the lowest-entropy cell, constraints propagating outward. Overtone contains the literal version of every one of those words.

**So show both at once.** Left: WFC laying down the maze, with its Shannon entropy over remaining tile options. Right: the walker on the finished maze, with its von Neumann entropy. Two entropies, two collapses, side by side. One is a metaphor and one is physics, and after thirty seconds a reader understands the difference better than a page of text could teach them.

Nobody has done this. It is free, it is funny, and it is genuinely instructive.

## 4. Endless possibilities: the archive

One trained agent is a result. **An archive of agents is a world**, and it is the honest answer to "endless possibilities."

Use **MAP-Elites** (Mouret & Clune, 2015). Instead of maximising return, maintain a grid over *behaviour descriptors* and keep the best agent in each cell:

```
descriptors (the axes of the Menagerie):
    x:  dim(g)              — algebraic expressiveness
    y:  transport exponent β — how the agent moves
    z:  effective χ          — how classical it really is
fitness: return
```

Every cell holds a genuinely different creature: a low-`dim(g)`, high-`β`, low-`χ` agent is a fast, simple, classically-simulable one; a high-`dim(g)`, low-`χ` agent is expressive but secretly a tensor network. The archive makes the whole trade-off space visible at once.

Why this is the right algorithm here and not a gimmick: Part III establishes that large `dim(g)` implies vanishing gradients. **In a barren plateau, gradient descent is a random walk — and quality-diversity search is one of the few methods that still functions.** MAP-Elites is not decoration bolted onto the RL; it is the correct optimiser for the regime the physics puts you in. Say that in the docs.

**The visual:** the grid filling in over generations, cell colour by fitness, coverage percentage climbing. Watching a QD archive fill is quietly compelling, and every cell is clickable — click it and that agent loads into the Lattice with its sigil and stat block. The archive is both the results table and the character-select screen.

Nightly Actions runs (§1) grow the archive continuously and push it to the Atlas. **The Menagerie is never finished.** That is the endlessness worth having.

## 5. Indirect improvements, ranked by value per line of code

### 5.1 Sonification — the name finally earns itself

The project is called Overtone. The policy **is** a Fourier series. Map its reachable frequencies to audible pitches and play them.

As `λ` trains, the pitch slides. When it approaches the environment's frequency you hear **beating**, and the beat frequency falls to zero as it locks on. You hear the agent tune into resonance *before you see it*, because human pitch discrimination is better than reading a bar chart.

Web Audio API, perhaps 150 lines. It is almost certainly the highest impact-per-line item in the entire project, it makes the name mean something, and it is a real accessibility win.

Rules: **off by default**, one obvious toggle, never autoplay, and a visible mute that works instantly. Audio that surprises people gets the tab closed.

### 5.2 Permalinks and a gallery

Encode every configuration — seed, world, ansatz, coin, `λ`, `χ` — into a URL fragment. Every interesting state becomes shareable, and shared links are the cheapest distribution there is.

Then a `gallery/` directory of `.json` configs, accepting pull requests. Someone who lands a config in your gallery becomes an advocate for your repo. This is the least effortful star mechanic available and it costs one directory and a loader.

### 5.3 Curiosity via quantum Fisher information *(speculative — flag it as such)*

Intrinsic-motivation RL rewards agents for information gain. For a quantum walker there is a native measure: the **quantum Fisher information** of the state with respect to environment parameters — literally how much the state has learned about the world.

`r_intrinsic = ΔF_Q` is a principled curiosity signal that no classical agent has access to, and it reuses Part III's QFIM machinery directly. It may not work. Put it in `experiments/`, not in the claims, and report the outcome either way.

### 5.4 Performance, so the ambition is affordable

- **WASM SIMD** — stable across browsers, and the state-vector inner loop is exactly the workload it exists for.
- **OffscreenCanvas in a Web Worker** — the simulation must never block the render thread. With four agents racing plus live FFTs, it will otherwise stutter, and stutter reads as "unfinished."
- **Decouple step rate from frame rate.** Physics steps on its own clock; `requestAnimationFrame` draws whatever is current. Never interpolate frames of a discrete-time process (Part II §9).
- **Budget the frame.** If it does not fit in 16 ms, cut a panel. Never cut fidelity.

### 5.5 Colour, done correctly

Phase is cyclic, so the phase colormap must be cyclic and perceptually uniform (twilight, CET-C2). A linear ramp on a cyclic quantity creates a false seam — a visible discontinuity where the physics is smooth — and physicists will spot it immediately.

Then the accessibility consequence, which is also a correctness consequence: roughly 1 in 12 men has a colour-vision deficiency, so **never let hue be the only carrier of information.** Phase gets a redundant channel — short tick marks whose angle encodes phase, or a togglable contour overlay. This is not a compliance chore; it makes the visualisation legible to more people and forces a clearer encoding for everyone.

### 5.6 Package it as a research artifact

Cheap, and it changes how the repo is read:

- A **datasheet** for the Atlas: how generated, what seeds, what is missing, what it should not be used for.
- A `CITATION.cff` so citing is one click.
- A `results/` directory with raw run data, not just plots.
- One command that regenerates every figure in the README from scratch.

The last one is rarer than it should be, and reviewers notice.

## 7. Traps

- **Do not verify the Space tier by assumption.** Hugging Face changed this; re-read their docs before launch and put it in the release checklist.
- **Do not make the demo depend on Tier 2.** Free Spaces sleep. The static build must be complete on its own.
- **Do not let sigils become decorative.** If the mark stops being a deterministic function of the algebra, delete it — a meaningless glyph is worse than no glyph.
- **Do not autoplay audio.** Ever.
- **Do not let the stat block acquire an invented number.** The moment one line is authored rather than measured, the entire card becomes fiction and the project loses the thing that distinguishes it.
- **Do not claim WFC is quantum.** The whole value of that panel is the contrast.
- **Do not present MAP-Elites as a bolt-on.** It is the correct optimiser for barren-plateau landscapes; the docs should explain why, or a reader will assume it was added because the grid looked nice.
- **Watch the scope.** This is now four parts. Part III §12's minimum viable cut still stands, and from Part IV the two items that most repay their cost are **the Static Space deploy (M15)** and **sonification (M17)**. Everything else is elaboration.
